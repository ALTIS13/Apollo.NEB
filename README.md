# Apollo.NEB for Linux

Apollo.NEB — локальная панель добычи NEB: воркеры, телеметрия,
графики, история и температурная остановка. Portable 0.6 не зависит
от частной фермы Atlas.

## Установка

Распакуйте архив на Linux с Python 3.10+ и запустите от обычного
выделенного пользователя, без `sudo`. Установщик не скачивает майнер,
не меняет драйверы, группы и сеть и не начинает добычу.

```sh
./install.sh
~/.local/bin/apollo-neb serve
```

Откройте <http://127.0.0.1:18763> и введите заданный при установке пароль.
Панель запускается и без кошелька или воркера, в режиме настройки. Для
работы в фоне вместо первого вызова выберите
`./install.sh --service -- --totp`: это служба пользователя systemd.
Работа после выхода из учётной записи зависит от настроек ОС.
Воркеры не стартуют автоматически, в том числе после сбоя.

Доступ с другого компьютера без публикации HTTP:
`ssh -L 18763:127.0.0.1:18763 user@your-host`, затем откройте тот же
локальный адрес. Для своего обратного прокси настройте HTTPS, передайте
`--origin https://neb.example` и включите TOTP. Не публикуйте upstream.
Первый ключ TOTP выводится только в локальном терминале: не пересылайте его.

## Добавить майнер

1. Установите по инструкции разработчика совместимый драйвер и доверенный
   бинарник. Убедитесь, что выделенный аккаунт ОС видит устройство.
   Apollo.NEB не распространяет майнеры, драйверы и датасеты.
2. `~/.local/bin/apollo-neb devices` показывает PCI-адреса AMD/NVIDIA
   и доступные показания. Возьмите образец из [examples](examples/).
   Укажите свой исполняемый файл, датасет, если нужен, и PCI-адрес.
3. Остановите запущенную панель, сохраните параметры, запустите снова:

   ```sh
   ~/.local/bin/apollo-neb configure --workers ./my-workers.json --wallet YOUR_NEB_MAINNET_ADDRESS
   ~/.local/bin/apollo-neb serve
   ```

   Для службы используйте `systemctl --user stop apollo-neb` перед
   настройкой и `systemctl --user start apollo-neb` после неё.
   Запуск добычи — отдельное действие на вкладке **Воркеры**.
   Приватный ключ и seed панель не запрашивает.

| Нужно | Адаптер | Условия |
| --- | --- | --- |
| NEB на AMD | `suprminer-opencl` | PCI-адрес, однозначное соответствие OpenCL и температура. |
| NEB на NVIDIA | `suprminer-cuda` | PCI ↔ UUID CUDA и температура. |
| Другой майнер, включая CPU | `custom` | Доверенный бинарник и список аргументов. Для GPU майнер должен принимать PCI-адрес. |

Встроенные профили ориентированы на [инструкцию пула](https://neb.suprnova.cc/StartMining.html)
и [релизы Suprminer](https://github.com/ocminer/suprminer/releases).
Они не гарантируют совместимость любой модели оборудования и драйвера.
Для custom задайте буквальный массив `args`; допустимые подстановки:
`{pool}`, `{wallet}`, `{worker}`, `{device}`, `{dataset}`.
Подстановки `{pool}` и `{wallet}` обязательны. Используйте доверенный
майнер, работающий в foreground и не выводящий процессы из своей группы.
`log_format: "json-lines"` читает строки JSON с числовыми
`rate_hs`, `accepted`, `rejected`. При `none` хешрейт неизвестен;
панель не подставляет нули за отсутствующие данные.
Кастомный майнер работает с правами выделенного пользователя;
программный выбор GPU не является аппаратной изоляцией.

По умолчанию Suprnova EU TLS. Для другого совместимого пула задайте
`[{ "id": "...", "label": "...", "url": "stratum+ssl://HOST:PORT" }]`
и импортируйте `configure --pools FILE --pool ID`. Предпочитайте TLS:
открытый TCP не шифрует соединение.

## Поддержка автора

По умолчанию **0%** от Apollo.NEB. Владелец установки может выбрать
`./install.sh --service -- --accept-support`: это включает **0,5%**
на отдельный публичный адрес DevFee из `developer-support.json`.
Выделяется около 0,5% времени встроенных профилей Suprminer
на отдельные сессии поддержки. Это не удержание монет из выплат.
Майнер начинает на своём адресе. Смена и возврат видны в истории.
Пятиминутная сессия возможна только после накопления соответствующего
времени обычной работы. Custom-профили не переключаются. У пула и
майнера могут быть собственные комиссии.

Поддержка работает только внутри пользовательской службы
`apollo-neb.service` с `KillMode=control-group`: это ограничивает
дочерние процессы при падении панели. В foreground-режиме поддержки
нет. Отключение: остановить панель, выполнить
`configure --disable-support`, снова запустить. Без `--accept-support`
опубликованный адрес не используется.

## Защита и обновление

- GPU-воркер требует читаемую температуру перед стартом. При превышении
  порога или потере обязательного показания останавливается только его
  процесс, не другие службы и не питание узла.
- Для старта воркеров нужен Linux 5.3+ с доступным `pidfd`. Независимый
  наблюдатель останавливает группу, если панель аварийно завершилась.
  Запущенный бинарник не должен отсоединять подпроцессы от группы.
  Таймер сессии поддержки действует независимо от записи истории.
- Ядро, Hotspot и дополнительный HBM2 настраиваются в панели.
  CPU custom не имеет GPU-термозащиты. Изменять ватты из Portable нельзя.
- Настройки в `~/.config/apollo-neb`, состояние в
  `~/.local/state/apollo-neb`; при заданных XDG путях — там.
  Не публикуйте эти каталоги. Снимайте копию при остановленной панели.
- Для обновления остановите панель и запустите установщик новой версии
  с теми же путями. Пароль и состояние сохраняются, если не заданы
  новые значения. Старый каталог кода остаётся под
  `~/.local/lib/apollo-neb/`; при остановленной панели можно вернуть
  ссылку `current` на прежний каталог. Не откатывайте базу вслепую.
- В foreground завершайте процесс через Ctrl+C или SIGTERM. Для
  защиты от сиротских дочерних процессов используйте службу systemd.
