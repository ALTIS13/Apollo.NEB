# Apollo.NEB: установка без ручного редактирования

Переносимая панель работает от выделенного пользователя Linux без
`sudo`. Она не использует служебные данные Atlas, не меняет
драйверы и не запускает майнер без команды. Перед установкой
официального 0.7.1-rc.1 проверьте
[SHA-256 релиза и условия DevFee 0,5%](../README.md).

## Маршрут первого запуска

1. Распаковать проверенный архив, выполнить `./install.sh --run`
   или выбрать фоновую пользовательскую службу через `--service`.
   Пароль администратора задаётся один раз в терминале.
2. Войти по адресу <http://127.0.0.1:18763>. В разделе **Защита входа**
   при необходимости включить 2FA: повторить пароль, отсканировать
   локально построенный QR, подтвердить код, сохранить одноразовые
   коды восстановления. Для внешнего HTTPS 2FA обязательна. Данные
   для QR не покидают браузер.
3. Вставить публичный адрес в **Профиле пула** или создать кошелёк
   в разделе **Кошельки** официальным
   NEB Wallet на своём хосте; скачать зашифрованную резервную копию.
   Отдельный пароль кошелька оператор хранит у себя. Панель не подписывает
   транзакции и не выдаёт секреты открытым текстом.
4. Открыть **Воркеры → Добавить GPU** и выбрать проверенный пакет майнера.
   Загрузка выполняется только по явному действию и со сверкой
   контрольной суммы. Нестандартные исполняемые файлы остаются под
   контролем владельца хоста. Зарегистрировать GPU и только затем
   запустить выбранные воркеры или остановить группу.
5. Блок **Релизы** показывает результаты проверки официального
   репозитория, но не устанавливает обновление. Для установки надо
   остановить панель и явно запустить `apollo-neb upgrade --apply`.

## Ручная конфигурация

1. Установите совместимый драйвер и доверенный бинарник, при
   необходимости подготовьте датасет. Эти файлы не входят в
   Linux-архив панели. Команда `~/.local/bin/apollo-neb devices`
   читает доступные PCI-адреса AMD/NVIDIA и показания датчиков.
2. Возьмите [пример](../examples/), укажите бинарник, PCI-адрес и
   датасет, если он нужен. Для `custom` указывайте массив `args`,
   а не shell-команду. Допустимы `{pool}`, `{wallet}`, `{worker}`,
   `{device}`, `{dataset}`. Подстановки `{pool}` и `{wallet}`
   обязательны; custom GPU-майнер должен принимать `{device}`
   и действительно ограничивать работу именно этим устройством.
3. Остановите панель (для systemd — `systemctl --user stop apollo-neb`).
   Импортируйте файл и снова запустите панель:

   ```sh
   ~/.local/bin/apollo-neb configure --workers ./my-workers.json --wallet YOUR_NEB_MAINNET_ADDRESS
   ~/.local/bin/apollo-neb serve
   ```

   Для установленной службы вместо `serve` используйте
   `systemctl --user start apollo-neb`. Майнинг запускается отдельно.

Custom-бинарник работает с правами текущего пользователя Linux и должен
оставаться в foreground и в своей группе процессов. Панель не обеспечивает
аппаратную изоляцию и не может проверить, что произвольный двоичный файл
действительно использует переданный адрес. Не запускайте недоверенный
майнер и не кладите посторонние ключи под того же пользователя Linux.

Режим `log_format: "json-lines"` принимает числовые `rate_hs`,
`accepted` и `rejected`. С режимом `none` эти показатели
неизвестны. Ноль на графике отличается от пропущенного измерения.

Пул по умолчанию — Suprnova EU TLS. Для другого совместимого пула
импортируйте массив записей вида
`[{ "id": "...", "label": "...", "url": "stratum+ssl://HOST:PORT" }]`
через `apollo-neb configure --pools FILE --pool ID`. Обычный TCP
не шифрует соединение; предпочтителен TLS.

## Изоляция функций

На внешнем узле оператор сам устанавливает панель/агент и уже
настраивает воркеры. Подключение нод
не означает право на SSH, запись произвольных файлов или выполнение
команд: допустимы только связанные с конкретным узлом статусы и явные
команды запустить/остановить его зарегистрированные воркеры.
«В очереди» означает принятие запроса, не факт запуска.
При неизвестном исходе сначала проверьте состояние воркера;
панель не повторяет такую команду автоматически. Отзыв доступа
не останавливает уже запущенный майнер.

Настройки и состояние имеют разные приватные каталоги: по умолчанию
`~/.config/apollo-neb` и `~/.local/state/apollo-neb`. Они не входят
в релизный архив. Снимайте копию после остановки и не загружайте её
в репозиторий. Обновление сохраняет каталоги; откат к старому коду
требует подходящей ему резервной копии состояния и базы входа.
